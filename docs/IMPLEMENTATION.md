# 구현 계획서

작성 기준: `PRD.md`, `ARCHITECTURE.md`, `AGENTS.md` 및 1부 demo 화면

## 0. 구현 범위와 전제

대상은 KOBIS 데이터를 이용하는 박스오피스 조회(F1)와 매출·관객 인사이트(F2)다. 브라우저는 Next.js 화면과 내부 API만 호출하고, KOBIS 인증키와 Supabase 비밀키는 Route Handler 서버 환경변수에서만 사용한다. 아래의 `stale`은 만료됐지만 마지막으로 정상 저장된 데이터가 존재한다는 뜻이다.

## 1. 화면 상태

| 화면/상태 | 진입 조건 | 화면 표시 | 사용자 동작/전환 | API·데이터 조건 |
|---|---|---|---|---|
| 초기/입력 대기 | 조회 조건이 아직 선택되지 않음 | 기간·기간 유형 선택 UI, 조회 버튼, 안내 문구 | 유효한 조건 선택 후 조회 | API 호출 없음 |
| 로딩 | 유효한 조회를 제출함 | 스켈레톤 또는 로딩 표시, 중복 제출 방지 | 완료·빈 결과·오류로 전환 | 요청 진행 중 |
| 성공(최신) | 정상 응답, `stale=false` | 목록/차트/Top N, 기준일·갱신 시각 | 검색·기간 변경·인사이트 옵션 변경 | `200`, data 존재 |
| 성공(저장본) | 외부 호출 실패지만 사용 가능한 이전 캐시 존재 | 데이터와 함께 “최신 조회 실패, 저장본 표시” 배지, 재시도 | 재시도 가능 | `200`, `meta.stale=true` |
| 정상 빈 결과 | 유효한 기간이지만 데이터 배열이 비어 있음 | “선택한 조건의 박스오피스 데이터가 아직 없습니다.”, 다른 날짜 선택 | 날짜/기간 변경 | `200`, `data.items=[]` |
| 검색 결과 없음 | 영화명 검색어가 현재 목록과 일치하지 않음 | 검색어를 포함한 “일치하는 영화가 없습니다.”, 검색어 지우기 | 검색어 수정·초기 목록 복귀 | 전체 조회는 정상, 클라이언트 필터 결과 0 |
| 입력 오류 | 날짜 형식·기간 유형·days·top이 허용 범위 밖 | 필드별 오류와 수정 안내, 요청 미전송 | 올바른 값 입력 | 서버 `400` 또는 폼 사전 검증 |
| 외부 호출 오류(저장본 없음) | KOBIS 실패/응답 검증 실패, usable cache 없음 | 재시도 버튼과 일시적 오류 안내 | 재시도 | `502`(상류 응답 오류) 또는 `503`(서비스 불가) |
| 타임아웃 | KOBIS/DB 호출 제한 시간 초과 | 시간 초과 안내와 재시도 | 재시도 | `504` |
| 설정/DB 오류 | 서버 환경변수 누락·DB 읽기/쓰기 실패 | 일반 오류 안내, 민감정보 미노출 | 재시도 또는 운영자 조치 | `503`(의존 서비스 불가) |

모든 오류 상태는 오류 코드·KOBIS URL·키·DB 접속정보를 노출하지 않는다. F2는 기간(7/14/30일)과 Top(5/10)을 바꿔도 동일한 상태 모델을 사용한다.

## 2. 책임 분리

| 계층 | 맡는 책임 | 맡지 않는 책임 |
|---|---|---|
| 화면(Next.js Client/UI) | 기간·기간 유형·검색어·인사이트 옵션 입력, 즉시 형식 검증, API 호출, 로딩/성공/빈 결과/검색 결과 없음/오류 렌더링, 숫자 포맷·차트 표시, 재시도 | KOBIS 직접 호출, 비밀키 보관, 캐시 저장, 숫자 파싱·신뢰성 판정 |
| 서버(Next.js Route Handler) | 요청 스키마·범위 검증, 캐시 키 생성, Supabase 조회/업서트, KOBIS 호출·타임아웃·재시도 정책, 외부 응답 정규화와 필수 필드 검증, 통계 계산, HTTP 상태·`data/meta` 계약, 로깅/민감정보 제거 | 화면 레이아웃, 브라우저 필터만으로 데이터 신뢰성 보장 |
| DB(Supabase Postgres) | `period_type+target_date` 유니크 캐시, 정규화된 items와 fetched/expires 시각 저장, 인덱스·upsert·트랜잭션, 최신/이전 저장본 조회 | KOBIS 호출, API 응답 형식 결정, 화면용 차트 계산 |

## 3. 내부 API 계약

### 엔드포인트 한 줄 정의

- `GET /api/box-office?date=YYYY-MM-DD&periodType=daily|weekly|weekend`
- `GET /api/insights?days=7|14|30&top=5|10`

### 요청·응답·실패 계약

| API | 요청 파라미터 | 성공 응답(`200`) | 실패 HTTP 코드 및 의미 |
|---|---|---|---|
| `/api/box-office` | 필수 `date`(정확한 `YYYY-MM-DD`), `periodType`(`daily\|weekly\|weekend`) | `{ "data": { "items": [{ "rank": 1, "movieCd": "...", "movieNm": "...", "openDt": "YYYY-MM-DD|null", "salesAmt": 0, "audiCnt": 0, "salesAcc": 0, "audiAcc": 0 }] }, "meta": { "periodType": "daily", "targetDate": "...", "fetchedAt": "...", "expiresAt": "...", "stale": false, "source": "cache|kobis" } }` | `400` 파라미터 오류, `502` KOBIS 비정상 응답/정규화 실패, `503` KOBIS·DB 사용 불가 또는 설정 오류, `504` 외부/DB 타임아웃 |
| `/api/insights` | 필수 `days`(7/14/30), `top`(5/10) | `{ "data": { "trend": [{ "date": "YYYY-MM-DD", "salesAmt": 0, "audiCnt": 0 }], "topMovies": [{ "rank": 1, "movieCd": "...", "movieNm": "...", "salesAmt": 0, "audiCnt": 0 }], "totals": { "salesAmt": 0, "audiCnt": 0 } }, "meta": { "days": 7, "top": 5, "stale": false, "source": "cache|kobis", "generatedAt": "..." } }` | `400` days/top 오류, `502` 원천 데이터 정규화 실패, `503` 필요한 기간 캐시를 확보하지 못함/DB 불가, `504` 데이터 수집 시간 초과 |

오류 본문은 공통으로 `{ "error": { "code": "VALIDATION_ERROR|UPSTREAM_ERROR|SERVICE_UNAVAILABLE|TIMEOUT", "message": "사용자에게 보여줄 안전한 문구", "requestId": "..." }, "meta": { "stale": false } }`를 사용한다. 검색어는 API 파라미터가 아니라 목록 응답에 대한 화면 필터이며, 결과 0은 오류가 아니다.

## 4. 요청 처리 순서·캐시·제한 시간

### 순서

1. **입력 검증**: 날짜 정규식과 실제 날짜, `periodType`, `days`, `top` 허용 목록을 검증하고 실패 시 즉시 `400`을 반환한다.
2. **캐시 조회**: `periodType + targetDate`를 키로 Supabase에서 조회한다. `expires_at > now()`인 정상 캐시는 즉시 반환한다. 만료 캐시는 `staleCandidate`로 보관한다.
3. **외부 호출**: 캐시 미스/만료 시 KOBIS URL을 서버에서 구성하고 `KOBIS_API_KEY`로 호출한다. 응답 JSON, 필수 필드, 숫자 변환·범위를 검증한다.
4. **저장**: 검증된 숫자형 데이터만 캐시에 upsert하고 `fetched_at=now`, `expires_at=now+TTL`로 저장한다. 저장 실패는 데이터 반환을 성공으로 위장하지 않되, 이미 확보한 데이터의 출처를 명시한다.
5. **저장본 대조**: upsert 후 동일 키를 다시 읽어 필수 필드·개수·기준일이 요청과 일치하는지 확인한다. 불일치하면 오류로 처리하고 기존 저장본이 있으면 stale 정책을 적용한다.

### TTL·제한 시간·실패 처리

| 대상 | 기본 정책 | 실패 처리 |
|---|---|---|
| 일간 캐시 | 다음 갱신 시점까지(기본 24시간, 운영 환경변수로 조정) | 만료 시 KOBIS 재조회 |
| 주간·주말 캐시 | 최소 6시간(기본 6시간, 환경변수로 조정) | 만료 시 KOBIS 재조회 |
| KOBIS HTTP | 연결 2초, 전체 5초, 필요 시 1회만 짧은 재시도 | 시간 초과 `504`, HTTP/JSON/필드 오류 `502` |
| Supabase 조회·저장 | 작업당 2초, 전체 Route Handler 예산 8초 | 시간 초과 `504`, 연결/권한 오류 `503` |
| 캐시 미스 후 외부 실패 | 마지막 정상 저장본이 있으면 `200 + stale:true` | 없으면 `502` 또는 `503`, 원인에 맞는 재시도 버튼 |
| 저장본 대조 실패 | 해당 응답을 신뢰하지 않음 | 이전 정상 저장본이 있으면 stale, 없으면 `503` |

외부 호출 실패 시 만료 캐시를 먼저 반환하고, stale 여부와 `fetchedAt`을 반드시 표시한다. 캐시가 없을 때 임의의 빈 성공 응답을 만들지 않는다. 동시 미스는 동일 키에 대한 중복 KOBIS 호출을 줄이도록 짧은 락/중복 제거를 후속 최적화로 둔다.

## 5. 우선순위와 구현 순서

| 순서 | 범위 | 완료 확인 기준 |
|---:|---|---|
| P0-1 | 환경변수·Supabase 캐시 스키마/인덱스·서버 전용 클라이언트 | 비밀키가 클라이언트 번들에 없고, 키 유니크·TTL 필드가 존재하며 마이그레이션이 재실행 가능 |
| P0-2 | 공통 스키마/숫자 파서/오류 타입과 `/api/box-office` | 정상·빈 배열·400·502·503·504 및 stale fallback 테스트 통과 |
| P0-3 | F1 화면과 전 상태 UI | 기간 선택, 목록 필수 필드, 검색 필터, 로딩/빈 결과/검색 결과 없음/오류/재시도가 demo에서 동작 |
| P0-4 | 기간별 수집 보강 및 저장본 대조 | daily/weekly/weekend 모두 올바른 `weekGb`, 정렬·숫자 타입·기준일 검증 통과 |
| P1-1 | 인사이트 집계 모듈과 `/api/insights` | 7/14/30일 trend, Top 5/10, totals가 동일 원천 데이터로 재현되고 부분 캐시 정책이 명확함 |
| P1-2 | F2 차트·Top 카드·보조 지표 | 선택 옵션 변경, 차트 로딩/빈 데이터/오류/stale 상태와 숫자 단위 표기가 동작 |
| P1-3 | 통합·E2E·접근성·관측성 | `npm run lint`, `npm run typecheck`, `npm test`, E2E가 통과하고 requestId 기반 오류 추적 가능 |
| P2 | 동시성 락, 백오프/사전 수집, 성능·캐시 적중률 개선 | 기능 회귀 없이 호출량·응답시간 지표가 기준을 충족할 때만 진행 |

각 단계는 코드 리뷰 전에 해당 완료 확인 기준과 테스트 결과를 기록한다. P0가 끝나기 전에는 차트·성능 최적화보다 데이터 신뢰성과 오류 상태를 우선한다.

따라서 demo는 UI 검증의 출발점으로 유지하고, P0-1~P0-4에서 실제 데이터 경로와 모든 상태를 붙인 뒤 P1에서 인사이트를 실데이터로 전환한다.
